# 非 PUCT 搜索的 CPU 优化与扩大直接对局

## 结论

CPU 优化有效，但**没有实现同推理上限下超过 PUCT-31 的目标**。
固定输入 CPU 测试约快 3.87 倍；高速配置端到端约 52 ms，原 PUCT-31 约 67 ms，
但新留出集大失误更多。同批次的 PUCT 控制还更快，不能将批次合并当成算法优势。

共完成 **192 局直接对局**，全部无截断。保留原搜索预算、只做底层优化的稳定版，
在本次模型/预算/开局条件下，相对 PUCT-31 的等效 Elo 约 **-150**，相对原 PUCT-512 约 **-364**。
高速减量版更弱。小样本静态局面评分接近，不能推断实战棋力接近。
这些是条件化的相对估计，不是标准绝对等级分；区间和保守界见下文。

保留不改变搜索预算的底层加速，不将高速减量配置作为更强默认方案，原 PUCT 实现保持不变。

## 已确认的性能和局面结果

小模型与大模型检查点不变。本轮优化增量评估内核、内存复制、将军判断和重复局面状态维护，
再用旧开发集选择展开数与批次大小。没有使用新留出组或对局结果重新拟合参数。

CPU 固定校正输出测试（16 根、每根三次，不含 GPU 推理）中，中位耗时从 **84.55 ms 降到
21.84 ms，约快 3.87 倍**。48 次选着均未改变。单个原生 probe 从 3.66 µs 降到 1.67 µs。
这不是端到端棋力证据，正式质量和 GPU 延迟另测。

实现包括 AVX2 点积（保留标量回退与非有限数校验）、热路径只复制有效的 `2*width` 累加器，
只初始化有效激活/元数据，以及使用规则库的直接将军判断替代反复走子撤回。
根累加器完整初始化，未使用的热路径尾区间不被读取或做浮点复制。
发生吃子或兵步后清除旧可逆历史的重复标志，避免随后每个节点扫描不可能的重复和棋请求。
这不会清除实际棋谱历史，也不把未知值当成精确胜负。

96 根的 PyTorch/原生预测最大差约 **2.0e-6**。原生独立测试比较了随机合法着法、易位、
吃过路兵和升变的将军判断，并覆盖不可逆走子后的重复标志重置及新可逆重复。
完整测试及 PGN 导出修复后的最终检查在验证节列出；独立 UBSan 核心测试通过。

## 开发选择和固定配置

开发集明确复用上一轮的 32 个旧根，不计为新留出评测。首先保留既定质量选择规则选中的
512 展开、batch 8、双 CPU 预算各 16,384 节点版本。
随后在开发结果的 Pareto 候选中，增加相同大失误数、平均 CP 损失距质量版不超过 2 cp 的最快版本：
**128 展开、batch 16、将杀和 CPU 价值预算各 8,192 节点，大模型位置上限 32**。
两条配置在新留出评分和实际对局之前固定。高速版是固定的主要直接对局选手；另保留原搜索预算
仅做底层优化的版本，防止把减少展开的损失混同于整个非 PUCT 方案的上限。

选择记录：`output/cpu-speed-20261031/{plan-before-development,plan,selection,final-suite}.json`。

## 新留出组

96 个新源棋局根来自编号 97,150–98,261，和之前实验/训练棋局、此次对局开局分离。
与新小模型训练/验证标签精确键交叉为零，也排除旧 500 万训练数据的精确键。
固定同一大模型，轮换方法顺序、冷树、统一老师候选并集比较（100k 提议 +500k MultiPV）。
所有 96 根候选均有 CP 分数；没有含将杀标签的根，不能据此推断短将杀能力。

| 方法 | 平均 CP 损失 | ≥100 cp 失误 | 中位耗时 | 平均大模型位置数 |
| --- | ---: | ---: | ---: | ---: |
| 高速非 PUCT，128 / batch16 | 44.33 | 15 | 51.5 ms | 31.15 |
| 保守非 PUCT，512 / batch8 | 39.58 | 12 | 73.0 ms | 31.79 |
| 原预算 + 底层优化，512 / batch4 | 38.65 | 12 | 90.7 ms | 31.97 |
| 原 PUCT-31，batch4 | 26.40 | 6 | 67.2 ms | 31.52 |
| PUCT-31，batch16 控制 | 29.30 | 7 | 45.6 ms | 30.97 |
| 原 PUCT-512，batch64 | 34.41 | 8 | 500.7 ms | 484.97 |

高速版原生 CPU 平均约 9.3 ms，每步约三个推理批次；原预算版原生 CPU 约 22.5 ms、九批。
因此端到端加速同时来自 CPU 内核与批次合并，不能把全部速度变化都归因于 CPU 内核。
同批次 PUCT 控制说明，不能仅靠加大自身批次就声称优于同预算 MCTS。

高速版相对原 PUCT-31 平均损失差 +17.94 cp，按根配对 bootstrap 95% 区间 [8.48, 28.61]，
大失误新增九个、未修复旧失误。速度目标有进展，效果目标没有达到，不能作为更强方案替换。
即使保留 512 展开，本批非 PUCT 的局面结果也未超过 PUCT。
数据：[`heldout-analysis.json`](evidence/cpu-speed-20261031/heldout-analysis.json)。

## 扩大直接对局的设计

从更晚的不同源棋局取 32 个开局，ply16–24，Stockfish 50k 评分绝对值不超过 100 cp。
每盘只取一个开局；根键与新小模型标签、旧大数据精确键无交叉。筛选不查看被测玩家结果。
双方使用同一个冻结大模型，固定每步搜索/推理上限；这是固定预算对局，不是等时间对局。

主要对照各交换颜色：高速版对原 PUCT-31 **64 局**、对原 PUCT-512 **64 局**。
另补原预算、仅底层优化的稳定版对 PUCT-31、PUCT-512 各 **32 局**，与高速版分开报告。
后者是新留出回归后追加的预定控制，不把不同配置结果混为一个选手。
原 PUCT 子树复用保持开启，非 PUCT 仍每步重建树；这是当前实现的实际差异。

每局保存完整 PGN、终局原因、双方选择次数、实际推理位置数和耗时；不完整对局排除，
不计为和棋。每局创建新玩家，清理上局缓存。实现支持按相同计划恢复已完成对局。

相对 Elo 使用 `400*log10(score/(1-score))`，只对这些模型、预算和开局分布有意义，不是绝对 Elo。
不把两局换色当成两个独立开局：按开局对重采样给近似 95% 区间，另给 Hoeffding 保守区间。
分数为 0 或 1 时 Elo 端点无界；所有开局同分时 bootstrap 会退化，应查看保守区间。
固定计划：`duel/plan.json`、`stable-duel/plan.json`，游戏结果不用于修改参数或提前停止。

## 高速版直接对局结果

128 局均完成，无截断，每个对照包含 32 个换色开局对：

| 对手 | 高速版胜 / 和 / 负 | 得分率 | 等效相对 Elo | 按开局对 bootstrap 95% 区间 |
| --- | --- | ---: | ---: | --- |
| 原 PUCT-31 | 11 / 8 / 45 | 23.44% | -206 | [-293, -137] |
| 原 PUCT-512 | 1 / 7 / 56 | 7.03% | -449 | [-648, -338] |

配对结果没有一个开局对达到超过 50% 的得分率，说明失利并非只来自几个孤立开局。
更保守的 Hoeffding 95% 分数区间分别为 [0,47.45%]、[0,31.04%]，对应 Elo 上端约 -18、-139，
下端无界。Bootstrap 区间是近似区间，不能外推为标准 Elo 或任意开局/时间控制下的差距。

全部 128 份记录通过 PGN 合法重放、终局/胜负/颜色核对和实际推理位置总数检查。
PGN 库默认导出会省略无合法吃法的过路兵字段，12 份起始 FEN 已从不可变的原始计划/JSON
恢复；原始 PGN 留有备份，走子及最终局面核对完全一致。实际对局始终使用原始 FEN，
修正只影响导出元数据和精确复现，不改变任何胜负。

数据：`output/cpu-speed-20261031/duel/{result,audit-final,fen-normalization}.json`。
原预算稳定版的独立对照另报，不与此处合并。

## 原搜索预算稳定版的直接对局

稳定版保留 512 展开、batch4、双 CPU 预算各 16,384 和大模型位置上限 32，只有底层内核
及等价重复状态维护优化。与高速版使用相同前 16 个开局，每个对照 32 局：

| 对手 | 稳定版胜 / 和 / 负 | 得分率 | 等效相对 Elo | 按开局对 bootstrap 95% 区间 |
| --- | --- | ---: | ---: | --- |
| 原 PUCT-31 | 7 / 5 / 20 | 29.69% | -150 | [-293, -44] |
| 原 PUCT-512 | 0 / 7 / 25 | 10.94% | -364 | [-523, -255] |

更保守的 Hoeffding 95% 分数区间分别为 [0,63.64%]、[0,44.89%]；后者的 Elo 上端约 -36，
前者包含相等甚至领先的可能。因此不能把稳定版对 PUCT-31 的点估计当成精确常数。
直接对局总体不支持其已达到 PUCT 的强度。

同前 16 个开局、同 PUCT-512 对手，稳定版比高速版平均多得 4.69 个百分点，
配对 bootstrap 区间 [-1.56,+10.94] 个百分点，仍跨零，不能精确量化减量配置的棋力损失。
两套非 PUCT 配置均明显落后于本次 PUCT-512，差距并非只来自高速版。

所有稳定版棋谱也通过合法重放、终局/胜负/颜色及实际推理位置总数核对。
对 PUCT-31 的稳定版实际每次选择平均评估 22.38 个大模型位置，PUCT-31 为 25.64，
说明“相同预算”是相同的 32 位置上限，并非强行消耗相同位置数。
比赛中的平均选择耗时分别约 64.8 / 52.9 ms；受局面与缓存影响，它们不能替代冷树延迟测试。

数据：[`duel-analysis.json`](evidence/cpu-speed-20261031/duel-analysis.json)、
`stable-duel/result.json`、`stable31-duel/result.json`。

## 验证与当前采用状态

实验期间原 PUCT 子树复用保留，非 PUCT 每步重建树；这影响实际强度，但本轮没有用消融
把差距定量归因于某一项。128 展开、CPU 预算和批次改变也同时存在于高速配置，不能把它们
各自的损失从本次对局中单独拆出。

底层内核加速可保留。高速配置在开发集上表现可接受，但未泛化到新留出集和直接对局，
不作为强度升级部署。保守批次版同样没有在新留出组超过 PUCT。
后续若继续研究，需要检验排序误差累积与跨步搜索复用，继续压缩 CPU 本身不足以证明强度提升。

新小模型数据的按棋局隔离和精确键排除已检查，旧大模型的整盘棋训练来源重叠仍未知。
开局来自同一份历史 PGN，且经过老师平衡筛选；相对 Elo 不能外推到任意开局、其他模型或时间控制。
保守概率界也依赖将开局对视为独立抽样的假设，不是开局集合以外的无条件保证。

最终完整测试 **142 passed in 25.75s**，包含不合法 EP 字段的 PGN 精确导出回归测试；
UBSan 原生测试（包括本机 AVX2 编译）、Python 编译检查和 `git diff --check` 均通过。
机器可读汇总、匹配时源码/二进制/模型指纹及审计路径：
[`cpu-speed-20261031.json`](evidence/cpu-speed-20261031.json)。
