# L4 实测与训练配置

推荐 `configs/phase2-l4.json`：microbatch **64**，梯度累积 **16**，有效 batch **1024**，原生 BF16，`torch.compile`，fused AdamW，原生 SDPA，DataLoader workers=2，CPU 算子线程=2。保留学习率 5e-5、100 步预热、Q 200 步预热及原有 loss 权重。

64–128 是已测方案中的优选区间，选择 64 是因为吞吐略高且显存更省。不能将显存占满视为高效利用 GPU；该工作负载的 GPU 利用率已经接近 100%，功耗约 72 W。没有人为超频或修改功耗上限。没有做模型量化或降低模型参数量。

## 测试条件

本轮实际创建 NVIDIA L4，CUDA 可见显存 22.034 GiB，12 vCPU，PyTorch 2.11.0+cu130。模型为完整 155000581 参数、16 层、宽度 896、14 heads 的现有网络。性能测试随机初始化 seed=42，不是恢复原第 10000 步权重，不代表棋力提升。

数据是已有评估数据的两个真实训练分片，共 32768 局面；SHA256 见 `data-provenance.json`。使用正式 policy/Q/value 损失、反向传播、梯度裁剪、fused AdamW、CPU 数据加载和 GPU 传输，不是只计 forward。回放测试复用这些分片作为回放输入，并屏蔽回放的 Q/value 标签，检验实际回放执行路径；**并未读取 Drive 中的人类棋谱缓存**。

每组采用独立 CUDA 子进程，预热 2–3 个完整优化器 step，再计时 5–10 step；有效 batch 始终是 1024。显存统计包含模型、梯度、优化器和激活；同步 CUDA 后计时。监测 GPU 利用率、功耗、频率和温度。不是长时间热稳定性测试，各方案运行温度与频率并非严格受控；小幅差异不能当作硬件普适定律。

## 后续带回放对照

| Batch × accum | 编译 | 局面/秒 | 峰值分配 GiB | 平均温度 °C |
|---|---|---:|---:|---:|
| 128 × 8 | 否 | 461.6 | 6.81 | 77.1 |
| 64 × 16 | 否 | 487.1 | 4.76 | 80.1 |
| 64 × 16 | 是 | 527.9 | 4.73 | 77.1 |
| 128 × 8 | 是 | 513.4 | 6.74 | 80.0 |

64 的编译版相对相同 batch 的原生带回放版快 8.4%。首次编译测试的完整预热约 38.5 秒，之后进程复用编译缓存的预热约 9.7 秒。预热包含实际 warmup step，并非纯编译耗时。对 3000 步训练，额外编译开销可摊薄；验证模式和最后一个不足 batch 的形状可能额外触发编译。

FP16 batch64×16 测得 472.8 局面/秒，BF16 的实测表现和数值范围更适合此 L4。0 worker 的对照约 502.6 局面/秒，未显示优于 2 worker 的可靠收益；保留 2 worker。各组温度不同，精度/worker 差异仅作本次配置参考。

## 预算与落地

以选中方案 527.9 局面/秒估算，3000 步纯训练约 **97.0 分钟**，还需加上编译、验证、对弈、保存与同步时间。当前账户在测试时的 L4 计费速率是 1.94 compute units/小时，对应上述纯训练约 **3.14 units**；不含额外流程，也不是固定价格承诺。

启动脚本默认创建 L4，远端按 GPU 名称选择 `configs/phase2-l4.json`。`NC_GPU=T4` 可继续使用原 T4 配置。正式训练仍使用原第 10000 步权重和完整数据；本轮仅做性能调优和集成检查。Drive 账户授权问题不影响本轮基准，但正式训练读取人类回放缓存及持久化仍需挂载 Drive。

原始结果见 `all.json`、各组 JSON/log，汇总见 `results.csv`。历史 T4 的 261.5 positions/s 来自不同测试口径，因此不据此宣称严格的 L4/T4 加速倍数。
