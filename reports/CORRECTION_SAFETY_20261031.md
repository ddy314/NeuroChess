# 限制错误校正与独立 CPU 战术搜索

## 结论

完成三组共 192 个新棋局根的对照，以及七种配置各八局、共 56 局实战。
**不应机械保护小模型排序**：正式主方案中的根强保护把大失误从 8 次增加到 17 次，拒绝采用。
只在有完成 CPU 深度结果时限制校正的追加方案也没有改善。
这表明原大模型的校正在不少局面中是有益的，不能因为个别反例就统一降低其作用。

有正面证据的是独立 CPU 战术搜索：两批普通留出组的大失误分别从 8 降到 6、从 7 降到 6，
但配对区间仍跨零；专门战术组修复一个被将杀选择、没有引入新的同类错误。
在 16 个两步/三步将杀根中，14 个能在调用大模型之前完成证明，推理节省明确。
实际对局未确认整体增强，低预算 PUCT 仍有很强的速度/效果竞争力。
默认参数及权重保持不变，CPU 搜索作为显式实验模式保留。

## 实现与对照约束

本轮保持旧大模型和上一轮 CP + 排序小模型检查点冻结，只改变搜索与校正。
实现三类可独立开关的机制，默认均关闭：

1. 神经网络校正的局部变化幅度限制，避免直接价值和候选 Q 无限制覆盖当前参考。
2. 根分数相对不可变小模型初始估值的偏移限制，防止多层备份累计绕过局部限制。
3. 独立 CPU 将杀证明，以及带强制应手延伸的 CPU 价值搜索，分别设置节点预算。

具体参数、语义和使用入口见 [`SEARCH_SAFETY.md`](../docs/SEARCH_SAFETY.md)。
两个幅度限制都不是置信区间；小模型初始排序错误时，也可能阻止有益校正。
启发式价值搜索也可能评错，只有独立将杀证明允许写入精确胜负。

设计参考官方 Stockfish 18 的
[search.cpp](https://github.com/official-stockfish/Stockfish/blob/sf_18/src/search.cpp) 与
[movepick.cpp](https://github.com/official-stockfish/Stockfish/blob/sf_18/src/movepick.cpp)：
区分静态评估与搜索结果、被将军时检查应手，以及强制着法优先的排序。
这是独立实现，没有复制其调参常数，也没有移植其 TT、SEE 或 LMR。

## CPU 预算与证明边界

将杀递归最多 16,384 个节点，根孩子与攻击方向分别获得额度，迭代搜索深度。
攻击方可以选将军、吃子或静着，防守方全部合法回应必须成立。
深度不足、额度耗尽和找不到证明都保持未知，不会判为已证明安全或必败。
模型输出、静态截断和不完整 CPU 价值都不能生成精确胜负。

另有最多 16,384 个 CPU 价值节点：全宽 alpha-beta，深度最多 2，有限应将/唯一应手延伸，
随后吃子、升变及首层将军静态搜索。应将节点不用静态 stand pat 截断。
只采用完整完成的深度作为启发式参考；不完整结果丢弃。
CPU 预算不计入神经网络位置预算。运行时不调用 Stockfish，老师只用于离线评测。

旧反例的 `Qxf7` 实际并不将军，它是吃子后的将杀威胁。上轮把它写作 `Qxf7+` 已更正。
只搜索将军链不能覆盖该例，因此新证明器纳入静着。
独立测试确认：即使大模型给 `Kh8` 极高先验，CPU 证明也能在预算内排除这条三步被将杀变化。

## 新留出组与正式方案

冻结 96 个源棋局编号 63,943–79,049 的新根局面，均晚于此前训练、验证与两批评测棋局。
每盘只取一根；与新小模型训练/验证标签的精确键交叉为零，也排除旧 500 万数据中的精确键。
这不证明原大模型的训练来源按棋局独立。

所有 Minimax 使用相同小模型、512 次展开、batch 4、根先验权重 0.1、目标一致化和按节点探索。
局部与根幅度阈值固定为 0.15 WDL 单位；将杀最大深度 7；CPU 价值最大深度 2。
主比较是全部机制组合对原搜索，另保留校正、根保护、证明、CPU 价值的消融。
神经网络位置上限分别为 32 和 16，并有 PUCT-15、31、原 PUCT-512 对照。
这些参数没有用新留出组的结果拟合。

开发预运行因旧败局回归显示局部限制不足而终止，源与部分日志归档到 `development-*`。
在检查新组结果之前增加根幅度限制，正式结果完整重跑并固定二进制；不混用预运行结果。
计划和源指纹：`output/correction-safety-20261031/{plan,suite,source-sha256}.json`。

老师用 100k nodes 提议着法，再用 500k nodes 对所有方法候选并集统一 MultiPV 比较。
CP 损失只相对这个候选集合，不是数学最优损失。含将杀标签的根另报，避免 WDL 饱和隐藏问题。
每步耗时包括额外 CPU 工作，神经网络位置数与批次数分别记录。

## 验证

完整测试 **137 passed in 26.23s**，当前源码的独立 UBSan 原生测试通过，覆盖 negamax 符号、
校正幅度、根排序限制、精确胜负越过限制、三步将杀和资源耗尽保持未知。
日志：`output/correction-safety-20261031/tests-confirm.txt`。

## 第一组：正式主方案及消融

96 个根中 95 个的候选并集全部有 CP 分数，1 个含将杀标签。

| 方法 | 平均 CP 损失（95 根） | ≥100 cp 失误 | 平均大模型位置数 | 中位耗时 |
| --- | ---: | ---: | ---: | ---: |
| 原搜索 | 30.78 | 8 | 31.57 | 115.9 ms |
| 局部校正限幅 | 30.59 | 8 | 31.52 | 117.1 ms |
| 再限制根价值偏移 | 65.96 | 18 | 31.65 | 116.4 ms |
| 只加将杀证明 | 30.78 | 8 | 31.55 | 125.6 ms |
| 将杀证明 + CPU 价值搜索 | 27.36 | 6 | 31.55 | 156.2 ms |
| 全部机制组合（正式主方案） | 62.17 | 17 | 31.63 | 157.2 ms |
| 全部组合，16 位置上限 | 61.34 | 17 | 15.80 | 125.5 ms |
| PUCT-15 | 30.42 | 8 | 15.79 | 35.1 ms |
| PUCT-31 | 29.96 | 8 | 31.56 | 66.4 ms |
| 原 PUCT-512 | 35.35 | 9 | 471.74 | 497.4 ms |

正式主方案减原搜索的平均损失差 +31.39 cp，配对 bootstrap 95% 区间 [6.25, 60.21]。
修复四个大失误、同时引入十三个，方向明显不利，不以次要方案的正面结果替代这个主结果。
根限制覆盖了 96 个最终候选中的 66 个，将错误初始排序也锁住了。

CPU 价值搜索减原搜索的差为 -3.42 cp，区间 [-13.91, +5.87]；修复三个大失误、新增一个。
这是探索性的积极结果，不能据此宣称稳定优于 PUCT，因而追加独立确认组。
证明预算实际平均使用约 13,884 节点，CPU 价值约 9,393 节点，平均 27.4 个根孩子完成参考搜索。
每步大模型约 8.91 个推理批次，与原搜索相近，位置数未增加。

数据：[`analysis.json`](evidence/correction-safety-20261031/analysis.json)。

## 第三组：独立短将杀与防守战术子集

前两组随机根只有两个含将杀标签的案例，不足以评估短将杀保护。于是另外从源棋局编号
94,492–96,659 中取 32 盘不同棋局，使用 Stockfish 50k nodes 独立筛选，完全不查看被测玩家输出：
16 个获胜将杀根（6 个两步、10 个三步），16 个实战走子导致短将杀而老师找到未报告被将杀
替代着法的防守根。后者不意味着一定能守和。根键与新小模型数据交叉为零。
这是有意按类别分层的战术挑战，不能代表日常局面的发生率。

最终仍用统一 500k 候选比较重新评分，参考着法只交给评测老师，不交给玩家。

| 方法 | 16 个防守根中选择被将杀变化 | 32 根平均大模型位置数 | 16 个进攻根中零大模型推理 |
| --- | ---: | ---: | ---: |
| 原搜索 | 4 | 19.59 | 0 |
| 只加 CPU 将杀证明 | 3 | 16.25 | 14 |
| 独立 CPU 搜索 | 3 | 16.25 | 14 |
| CPU，16 位置上限 | 4 | 8.16 | 14 |
| PUCT-15 | 7 | 12.56 | 0 |
| PUCT-31 | 7 | 22.41 | 0 |
| 原 PUCT-512 | 4 | 122.63 | 0 |

32 根中各方法都没有错过老师报告的获胜将杀。CPU 版相对原搜索修复一个防守失误、没有新增；
16 位置版修复一个、另引入一个，因此不能把推理减半与全面减错同时宣称为已实现。
进攻根 CPU 版中位耗时约 5.3 ms，14/16 在大模型调用前完成证明。
防守根 CPU 版仍平均使用约 31.63 个位置；将杀证明没有解决剩余三个错误。

这是本轮最明确的推理节省证据，但防守误差减少仅一个，样本不足以说明普遍增强。
数据：[`tactical-roots/plan.json`](evidence/correction-safety-20261031/tactical-roots/plan.json)、
[`tactical-analysis.json`](evidence/correction-safety-20261031/tactical-analysis.json)、
[`tactical-by-kind.json`](evidence/correction-safety-20261031/tactical-by-kind.json)。

## 实际对局与采用状态

固定第一组前四个开局、交换颜色，对手 Stockfish 18 每步 1,000 nodes，每种配置八局：

| 方法 | 胜 / 和 / 负 |
| --- | --- |
| 原搜索 | 2 / 2 / 4 |
| 正式全组合，32 上限 | 1 / 3 / 4 |
| 正式全组合，16 上限 | 1 / 3 / 4 |
| 独立 CPU 搜索 | 1 / 3 / 4 |
| 有 CPU 参考才限幅，16 上限 | 1 / 3 / 4 |
| PUCT-31 | 1 / 1 / 6 |
| 原 PUCT-512 | 2 / 3 / 3 |

56 局均无截断，但只有四个独立开局对，不能据此给 Elo 或稳定排名；CPU 版没有显示实战增强。
不同阶段根难度和候选集合不同，三个组的均值未混合成一个排名。

保留独立 CPU 搜索及全部消融入口，校正限幅默认零，不替换当前默认模型或 PUCT。
CPU 静态搜索是继续优化的可用起点；后续应按棋局独立扩大确认样本、提高 CPU 搜索效率，
以及学习“何时校正有益”的可靠性，而非把初始小模型排序固定为真值。
