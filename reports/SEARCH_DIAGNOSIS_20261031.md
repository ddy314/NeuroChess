# 搜索漏算诊断与受控改进

## 结论

问题同时来自评估、监督目标和搜索决策机制，不能归结为“小模型太小、学不到东西”。
扩大容量确实降低误差，但没有修复关键反例；小模型可以拟合新增难例，却未能可靠泛化。
更直接的问题是搜索访问局面上的估值误差、WDL 目标饱和，以及搜索对乐观误差的放大。
大模型的 WDL 校正也会判断错误，不能当作真值。

已实现并测试策略先验约束、根节点搜索/校正/选着目标一致化，以及预算内的最终候选复核。
前两项在比较样本中改善了结果；最终复核只保证检查流程，不能保证估值正确，保留为实验选项。
当前证据仍不足以用新搜索替换原 PUCT。

## 1. 从真实败局与已知反例复现

对上一轮四局败局的 160 次模型选着，使用本地 Stockfish 扫描，选出每局首个候选损失超过
100 厘兵的位置。保留完整走子历史进行冷树重放，四个原失误均能复现。扫描使用 50k nodes
提议与 100k nodes 的统一候选比较，随后以 500k nodes 复核；其中一例的差距降至 93 厘兵。
这些是有限预算老师认为有损失的位置，不一定是棋局首次转败的节点。

数据：[`old-game-audit/result.json`](evidence/search-diagnosis-20261031/old-game-audit/result.json)，
[`game-failure-replays/result.json`](evidence/search-diagnosis-20261031/game-failure-replays/result.json)。

另一个清晰反例是开发开局中的 `g5e4?`。搜索并未遗漏 `...f6e4`：错误根分支展开 421 次，
该反击节点展开 380 次，两者均接受过大模型直接校正；策略首选 `g5h3` 的分支却只展开 4 次。

在 `g5e4` 后，从黑方视角：

| 来源 | 估值 |
| --- | ---: |
| 原小模型 | -0.310 |
| 大模型 WDL | 约 -0.26 |
| Stockfish 100k nodes | 约 +267 cp，对应既有目标 +1 |

在 `...f6e4` 后，从白方视角，小模型给 +0.371，大模型约 +0.080，而老师约 -257 cp。
因此该例首先存在估值方向错误；增加相同类型的校正不会自动发现真相。

树与校正事件：`output/search-diagnosis-20261031/initial-case-tree.json`；
老师变化：`initial-case-teacher.json`。原型没有把概率估值当作精确胜负证明。

## 2. 排除实现错位，检查容量

小模型、较大模型分别检查 100 个随机合法历史局面，C++ 与 PyTorch 的预测最大差都约
2.4e-6，累加器增量更新与完整重建的最大差小于 1.4e-6。原有规则差分、negamax 符号、
精确证明边界和特殊走子测试也通过。未发现能解释上述量级误差的编码、视角或浮点实现错位。
这不等于对所有代码和局面的数学证明。

容量对照从头训练，使用相同的 500 万局面数据、30,000 步、batch 4096、种子 3171、优化器、
学习率与余弦退火，按相同验证子集选最佳检查点。完整验证集均为 51,086 个局面：

| 容量 | 参数量 | 固定训练样本 MSE | 完整验证 MSE |
| --- | ---: | ---: | ---: |
| 128 / 32 | 107,073 | 0.18196 | 0.19145 |
| 512 / 128 | 526,593 | 0.14146 | 0.16402 |

容量扩大约 4.9 倍，完整验证 MSE 下降约 14.3%，说明容量有影响。但较大模型在上述关键变化上
仍把黑方优势评为约 -0.308，未修复方向错误。该对照只有两个尺寸、一个种子，不能据此确定
最优容量。两个模型训练完相同步数，选模检查点分别为 30,000 与 27,500 步。

在第一组 32 个比较局面中，较大模型加先验约束的平均候选损失为 17.31 cp，但每步中位耗时
约 0.876 秒，高于 PUCT-512 的约 0.499 秒。更大的模型有益，却不符合当前轻量目标。
该搜索对照使用较大新模型与原长期训练小模型，不是纯粹的等训练容量实验。

数据：[`capacity-analysis.json`](evidence/search-diagnosis-20261031/capacity-analysis.json)，
`capacity-critical-line.json`，`trained-native-parity.json`。搜索分层分析后来另行保留原始 EP
输入的修正序列化记录；训练/完整验证数字不受该序列化差异影响。

## 3. 搜索分布上的泛化比普通验证集差

在八个开发根局面及其真实搜索树中抽样，用 Stockfish 50k nodes 标注：

| 局面层级 | 数量 | 小模型 MSE | 大模型 WDL MSE |
| --- | ---: | ---: | ---: |
| 根局面 | 8 | 0.1161 | 0.0643 |
| 根的全部合法孩子 | 288 | 0.4003 | 0.1228 |
| 随机深层边界 | 64 | 0.5092 | 0.1842 |

这批搜索局面的分布与普通训练/验证局面不同。数值不代表全部国际象棋局面，也不是数学真值；
但它直接解释了为何普通验证 loss 看似改善，搜索中仍会被错误乐观的分支吸引。
逐层取极值并不消除这种误差，搜索还可能把更多预算投入错误分支。

进一步从 160 个不同 PGN 棋局生成 2,560 个搜索局面，用本地 Stockfish 50k nodes 标注。
训练/验证分别来自 128/32 个棋局，共 2,048/512 个局面；剔除了包含第一组保留根局面的 25 个
相关棋局。所有精确键去重、保留集排除、轨迹和有效编码均通过检查。

同起点、相同核心数据序列、相同步数和优化器的 10,000 步续训对照：

| 训练方式 | 边界训练 MSE | 按棋局分组的边界验证 MSE | 普通完整验证 MSE |
| --- | ---: | ---: | ---: |
| 不追加训练 | 0.5708 | 0.5530 | 0.1780 |
| 普通续训 | 0.5704 | 0.5536 | 0.1778 |
| 核心损失 + 0.25 边界损失 | 0.0426 | 0.5263 | 0.1865 |

小模型能拟合这些难例，不能说没有学习能力。但训练误差的大幅下降没有转化为验证改善，
普通分布还出现退化。少量、相关性强的边界标签导致过拟合，不能把继续重复训练当作解决方案。
这份新权重只保留为实验，不替换原权重。

数据：`frontier-teacher-v2/{roots,jobs,audit}.json`，
[`frontier-data-intervention.json`](evidence/search-diagnosis-20261031/frontier-data-intervention.json)。
其中边界验证应按对应 manifest 的棋局分组解释，不能套用普通数据的局面哈希划分说明。

## 4. 标签本身丢失了部分排序信息

扫描全部 5,000,000 个训练记录：

- 33.65% 的状态 W-L 目标绝对值不小于 0.99。
- 31.64% 的目标绝对值不小于 0.999。
- 25.12% 的目标绝对值不大于 0.01。
- 555,723 行中，全部已标注动作 Q 几乎同向饱和，而 policy 目标的最大/最小概率仍相差至少 0.1。

当前固定 ply=32 的 `sf16` 转换，把 -245 cp、-500 cp、-1000 cp 都映射为 -1；
-190 cp 映射为 -0.994。用这个标量作为唯一监督，无法保留这些候选之间的厘兵距离。
policy 的相对着法目标仍包含部分区别，小评估器当前只学习状态 W-L。

这不表示 WDL 是错误目标，而是它不适合作为当前原型唯一的精细排序信号。
扩大模型不能从被压掉的标签中恢复全部排序信息。后续应保留 CP 或相对排序监督，再做单独对照；
本轮没有把尚未训练验证的 CP 方案宣称为有效。

数据：[`target-saturation.json`](evidence/search-diagnosis-20261031/target-saturation.json)。
诊断中的 `oracle-WDL` 只是替换校正 WDL、保持原 policy/Q 的干预，**不是 CP 排序真值**。
它在八个开发位置显著改善结果，却仍会在真实败局中失误。

## 5. 搜索与校正的具体问题及修改

### 先验太弱，错误乐观值决定预算

原选择项只有很小且随访问衰减的先验奖励，最终按最大估值选着。
新增根决策分数 `search_value + 0.1 * log(prior)`，优先保留已有策略支持。
精确胜负的优先级独立于这个分数，极小先验的已证明将杀仍会被选择。

### 选着目标与搜索、校正目标不一致

仅改变最后选着，会让 CPU 仍按旧分数深入错误分支。新增 `align_root_objective=True`，
让根节点展开、根候选校正排序及最终选着使用相同目标。保留每十六次展开的探索机会。

### 固定锚定会削弱深层反驳，但不能简单删除

直接校正权重固定 .75，使每层后续搜索值只占 .25；连续多个已校正祖先会衰减深层信息。
独立固定树测试展示：即使边界值准确，错误父锚点也能保留错误选择。
但八位置消融中，删除锚定、按访问衰减、或仅查询深层边界均未稳定改善，部分明显恶化。
因此保留这些可复现实验开关，不把“去锚定”作为已验证修复。

### 最后一次校正后，可能选到没直接检查过的新候选

真实败局的 Stockfish-WDL 干预曾选中 `e1d2`：该根子节点没有直接校正，先验约 3.49e-5。
新增 `verify_final=True`，默认从总预算中预留最多八个位置，反复检查当前领先根候选；预算
耗尽后只在已直接评估或精确解决的合格候选中选取。没有子局面查询预算时使用策略回退，
且不会因先验很高而选择已证明必败的候选。总预算上限保持不变。

`final_candidate_checked` 只表示获得过直接价值头结果或精确解，不代表判断正确。
该约束在真实案例上也可能损失质量；例如某次复盘从正确的 `c3d5` 换成了有损失的 `e2c4`。
因此保持显式实验开关，默认关闭。它修复检查流程，不消除估值偏差。

## 6. 分批冻结局面的比较

除八个开发位置，还进行了三批各 32 个冻结根局面对照。都排除与完整 v2 数据相同的精确键；
后两批来自更晚的不同棋局，与边界增训棋局分组分离。原始基础数据的整盘棋/来源独立性仍未知。
每批修改前固定根与参数，算法二进制在运行开始时固定，避免编译切换污染实验。

老师先用 100k nodes 提议着法，再以 500k nodes 对各方法候选并集进行一次统一 MultiPV 比较。
“损失”相对于该候选并集，不相对于数学最优着法。不同批次候选集合和难度不同，分批保留结果。

第二批 32 个新根，原搜索/先验约束/目标一致化的平均损失分别为 16.78 / 13.44 / 10.84 cp；
PUCT-512 为 9.72 cp。目标一致化保持了约 0.116 秒中位耗时，而 PUCT-512 约 0.500 秒。

第三批再次使用新的棋局，检验目标一致化和最终复核：

| 方法 | 平均大模型位置数 | 中位耗时 | 平均候选损失 | 损失至少 100 cp 的位置 |
| --- | ---: | ---: | ---: | ---: |
| 原小模型 Minimax | 32.0 | 0.113 秒 | 70.16 cp | 9/32 |
| 先验约束 + 目标一致化 | 32.0 | 0.111 秒 | 58.75 cp | 8/32 |
| 同上 + 最终复核预算 | 24.0 | 0.096 秒 | 58.75 cp | 8/32 |
| PUCT-31，batch 4 | 32.0 | 0.066 秒 | 70.59 cp | 7/32 |
| PUCT-512，batch 64 | 478.7 | 0.498 秒 | 31.94 cp | 4/32 |
| 单次直接选着 | 1.0 | 0.0049 秒 | 108.41 cp | 11/32 |

最终复核开关在这一批没有发起额外尾部查询：探索阶段结束时领先候选都已检查，剩余预算
未使用，32 个选着与一致化版本全部相同。这是该批的实际观察，不保证其他局面也能省掉预算。
真实败局反例已经表明，不应据此把该开关视为普遍增强。

低预算 PUCT 也必须保留为对照：第一批它明显优于新搜索，第三批平均厘兵损失反而更高，
但大损失位置更少。不能只对比昂贵的 PUCT-512，就认定新搜索更划算或棋力更强。

数据：

- [`heldout-comparison-final/result.json`](evidence/search-diagnosis-20261031/heldout-comparison-final/result.json)
- [`phase2-comparison/result.json`](evidence/search-diagnosis-20261031/phase2-comparison/result.json)
- [`phase3-comparison/result.json`](evidence/search-diagnosis-20261031/phase3-comparison/result.json)

第一组 13 方法的首次运行在最后一个位置遇到源码过期检查，已废弃为未完成记录；
最终表使用随后固定二进制完整重跑的结果。对局配置输出的字段重名错误也已修复，
完成的四份合法棋谱与计数恢复后，按相同计划继续了剩余方法。

## 7. 实际对局与边界

固定同样两个既有开局、交换颜色，本地 Stockfish 18 每步 1,000 nodes，均无截断：

| 方法 | 胜 / 和 / 负 |
| --- | --- |
| 原 Minimax，上一轮记录 | 0 / 0 / 4 |
| 加先验约束 | 0 / 2 / 2 |
| 再对齐根目标 | 0 / 1 / 3 |
| PUCT-31 | 0 / 0 / 4 |
| 原 PUCT-512 | 1 / 1 / 2 |

只有两个开局对，不能据此排名或计算可靠 Elo。对局也未显示一致化版本已经超过 PUCT。
BF 当前仍重建每步的树，PUCT 有子树复用；这个差异影响对局，但不能解释冷树局面对照中的
全部差距。当前改进应作为实验模式提供。

数据：`arena-guarded/result.json`、`arena-aligned/result.json`。

## 8. 实现与验证入口

- `neurochess/native/best_first.cpp`：可调锚定、先验约束、目标一致化、尾部预算、完整树/校正轨迹。
- `neurochess/best_first.py`：显式参数、逐次统计和 `trace()`。
- `scripts/diagnose_best_first.py`：固定树、评估分层与机制消融。
- `scripts/audit_search_games.py` / `replay_search_failures.py`：从真实棋谱选点并保留历史重放。
- `scripts/distill_search_frontier.py`：本地老师标注、棋局分组、精确键和输入轨迹检查。
- `scripts/compare_search_variants.py`：固定二进制、输入指纹、轮换方法顺序的对照。

默认保留原型参数便于复现。改进实验示例：

```python
player = BestFirstPlayer(
    "output/cheap-minimax-20261031/student-selected/best.bin",
    network=network, expansions=512, neural_budget=32,
    root_policy_weight=.1, align_root_objective=True,
)
```

最终候选复核另加 `verify_final=True`，不是默认增强选项。
较大模型和边界增训模型均保留在 `output/search-diagnosis-20261031/`，没有自动替换原权重。

最终完整测试：**120 passed in 24.32s**。当前源码的独立 UBSan 原生测试通过，覆盖
minimax 符号、持久锚定和精确证明边界；Python 编译检查及 `git diff --check` 通过。
测试日志：`output/search-diagnosis-20261031/tests-final.txt`。
机器可读汇总与源文件哈希：[`search-diagnosis-20261031.json`](evidence/search-diagnosis-20261031.json)。

当前证据支持下一轮优先改善搜索分布上的评估泛化，并保留 CP/相对排序信息；之后再选择
CPU 预算允许的模型容量。继续增加同分布训练步数、廉价深度，或单纯增加校正次数，都不足以
保证消除已发现的失误。
