# CP、相对着法排序与扩大搜索边界数据实验

## 结论

管线已实现并实际完成本地 GPU 训练、两批共 192 个新棋局根位置的冻结对照和 40 局实战。
新边界训练流程改善了普通候选验证指标，但 **CP + 排序没有证实进一步减少实际战术漏算**。
相同数据的 WDL 对照发生 10 次至少 100 cp 的损失，CP + 排序为 11 次；平均损失略降，
配对差异区间跨零。不能把相对旧模型的改善全部归因于 CP 或排序。
同推理预算 PUCT-31 的耗时和实战结果也更好，因此本轮不替换默认搜索或权重。

留下了一个更具体的机制反例：新小模型已经排对候选，但不准确的大模型校正和搜索备份又把
顺序翻转。继续只增加小模型监督，不能解决这一类失误。

## 实验约束

本轮保留原始 CP、同次 MultiPV 中候选的相对排序和既有 WDL 监督。
三个新模型从头训练；训练前固定网络、种子、目标权重和验证选模标准。
最终评测根局面不参与训练或选模。旧模型和原 PUCT 作为冻结参考，未改变默认权重或搜索配置。

计划：[`experiment-plan.json`](evidence/rank-frontier-20261031/experiment-plan.json)。
实现说明：[`CP_RANK_DISTILLATION.md`](../docs/CP_RANK_DISTILLATION.md)。

## 数据与隔离

本地 PGN 中第 39,191 盘之后、双方等级分至少 1,600 的不同棋局，每盘随机取一个根。
按整盘棋固定分组，再由旧小模型以 128 次展开生成搜索边界。每根最多选择 16 个父局面，
包括根、候选孩子、主变边界和随机深层边界；每个父局面由本地 Stockfish 18 搜索
20,000 nodes，保留最多四条 MultiPV 及对应孩子的标签。

| 分组 | 棋局 | 父子训练组 | 有效标注状态 | 不同局面键 |
| --- | ---: | ---: | ---: | ---: |
| 训练 | 1,600 | 25,522 | 125,543 | 121,755 |
| 验证 | 400 | 6,376 | 31,350 | 30,387 |
| 最终评测 | 128 | — | 128 个冻结根 | 128 |

训练/验证状态总数 156,893，约为上一轮 2,560 个边界状态的 61 倍，含少量同组内重复状态。
训练与验证已标注键交叉为零，最终评测棋局已走前缀键也从训练/验证排除。
老师输入保留已走历史、搜索路径及原始 EP；400 组轨迹抽样重建和合法孩子检查通过。
评测根还排除了旧 500 万数据中的精确键；不能据此保证既有大模型的原始训练来源按棋局独立。

## 监督、训练和选模

主价值头继续输出 WDL，保持原生推理格式和大模型校正尺度一致。
CP 辅助头共享表示，用 Huber 损失拟合 `clip(raw_cp, -3000, 3000) / 600`；原始 CP 不裁剪存储。
将杀单独保存，不混入普通 CP 回归或排序。排序监督同父局面的候选孩子，按孩子的行棋方
视角取负，使用 CP 差的软概率；忽略小于 30 cp 的差距。
排序直接约束主价值头未压缩 logits，避免 WDL 饱和后完全没有排序梯度。

三个版本同为 128/32 网络，训练检查点含 107,106 个参数，其中 CP 辅助头 33 个参数。
导出的 CPU 模型只保留原来的 107,073 参数 WDL 网络，428,308 bytes。
辅助 CP 头未作为原生搜索的独立 CP 打分使用；本轮检验的是辅助监督和主头排序的效果。

本地 RTX 4060 Laptop GPU，batch 256 组，种子 431903，AdamW，初始学习率 0.0005、余弦退火，
每个版本实际完成 20,000 步、约 2,511 万状态训练曝光。验证每 1,000 步进行一次。
WDL / WDL+CP / WDL+CP+排序的 CP、排序损失权重分别为 `(0,0)` / `(0.5,0)` / `(0.5,0.2)`。
三个版本统一最小化验证 `WDL MSE + 0.2 * 排序 BCE` 选模，均选中第 3,000 步。

| 版本 | 验证 WDL MSE | 候选排序准确率 | 验证候选平均损失 | 候选损失 ≥100 cp 的组 |
| --- | ---: | ---: | ---: | ---: |
| WDL | 0.36101 | 69.52% | 35.75 cp | 656 / 6,321 |
| WDL + CP | 0.36169 | 69.66% | 35.39 cp | 641 / 6,321 |
| WDL + CP + 排序 | 0.35977 | 69.78% | 35.35 cp | 640 / 6,321 |

这里的候选损失仅相对该组老师标注的最多四个候选，不是完整搜索评测。
后续训练明显过拟合：20,000 步时三个版本的验证 WDL MSE 分别约 0.482、0.480、0.467，
没有采用最后一步权重。CP 辅助回归改善，主头排序验证增益较小，不能提前认定战术能力提升。

训练记录：[`training-summary.json`](evidence/rank-frontier-20261031/training-summary.json)。

## 冻结局面与实际对局

128 个新棋局根使用冷树、轮换方法次序，预热同一个冻结大模型。
Minimax 均为 512 次展开、最多 32 个校正位置、根先验权重 0.1、根目标一致化，最终复核关闭。
PUCT 保留原实现，分别为 31/128/512 次模拟，batch 4/16/64。
老师先用 100k nodes 提议着法，再用 500k nodes 对所有方法的候选并集进行统一 MultiPV 比较。
该冻结根评测从 FEN 开始；下面的旧败局重放保留完整历史。

其中 120 个根的全部候选都有 CP 分数，另 8 个根含老师将杀标签，分开报告。
CP 损失相对候选并集，不能当作数学最优着法损失或 Elo。

| 方法 | 平均 CP 损失（120 根） | 损失 ≥100 cp | 每步中位耗时 | 平均大模型位置数（128 根） |
| --- | ---: | ---: | ---: | ---: |
| 旧小模型 + 一致化搜索 | 42.08 | 14 | 118.1 ms | 31.07 |
| 新 WDL 对照 | 35.67 | 10 | 118.5 ms | 31.14 |
| 新 WDL + CP | 35.03 | 12 | 118.5 ms | 31.20 |
| 新 WDL + CP + 排序 | 33.40 | 11 | 119.4 ms | 31.15 |
| PUCT-31 | 28.60 | 11 | 67.7 ms | 31.06 |
| PUCT-128 | 28.35 | 12 | 156.6 ms | 123.98 |
| 原 PUCT-512 | 31.21 | 12 | 503.3 ms | 484.04 |
| 单次直接选着 | 33.95 | 14 | 5.2 ms | 1.00 |

CP + 排序减去同数据 WDL 的平均损失差为 -2.27 cp，按棋局根配对 bootstrap 95% 区间
为 [-10.55, +3.93]；修复了一个 ≥100 cp 失误，同时引入两个。
相对旧模型的差为 -8.68 cp，区间 [-21.28, +0.67]；修复四个大失误，引入一个。
这些区间和失误数没有给出稳定改进的证据。对照只用一个训练种子，不能判断不同随机种子的稳定性。

8 个含将杀的根中，旧模型漏掉一个老师判定的获胜将杀；新三个版本均未出现这类遗漏，
但均有一个局面选择了可避免的被将杀变化。PUCT-512 两类事件均为零。
“可避免”是有限预算老师在候选并集中找到一个未报告被将杀的选择，不意味着该选择能守和。
这些事件不能因为 WDL 都饱和为 -1，就在损失统计中当作无区别。

数据：[`comparison/result.json`](evidence/rank-frontier-20261031/comparison/result.json)、
[`comparison-analysis.json`](evidence/rank-frontier-20261031/comparison-analysis.json)。

同样前四个冻结开局，各交换颜色，对手为 Stockfish 18 每步 1,000 nodes：

| 方法 | 胜 / 和 / 负 | 截断 |
| --- | --- | ---: |
| 新 WDL 对照 | 1 / 2 / 5 | 0 |
| 新 CP + 排序 | 0 / 2 / 6 | 0 |
| PUCT-31 | 4 / 2 / 2 | 0 |
| PUCT-512 | 4 / 1 / 3 | 0 |

只有四个开局对，不能计算可靠 Elo，也不能据此认定 PUCT-31 强于 PUCT-512。
但这批实战没有支持 CP + 排序已胜过原搜索。PUCT 的子树复用与 Minimax 每步重建树的差异保留，
它影响实际对局；冷树根评测则排除了跨步树复用的影响。
数据：`arena-wdl/result.json`、`arena-cp-rank/result.json`。

## 剩余漏算的机制检查

四个旧败局关键根均未与新训练/验证标签键重叠。用完整历史、新的统一候选比较重放，
CP + 排序仍没有修复其中 `e3g5?` 的 167 cp 损失。更值得注意的是，新小模型的单步排序已经正确：

| 根候选 | 老师 CP | 小模型 CP 辅助预测 | 小模型 WDL | 大模型直接校正 WDL | 最终搜索值 | 根分支展开 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `e2g3` | -14 | +61.5 | +0.521 | -0.119 | -0.081 | 1 |
| `e3g5` | -181 | +21.5 | +0.381 | +0.004 | -0.013 | 298 |

所有分数已转换到根的行棋方视角。小模型绝对值仍偏乐观，但 CP 和 WDL 都把安全候选排在前面。
大模型校正给出相反顺序，持久权重 0.75 的锚定与后续搜索再次改变排序；根策略先验也偏向坏着。
这说明此例的剩余问题包含校正可靠性与预算分配，不能解释为“小模型仍完全没学会”。
另一个旧败局里，CP + 排序选择的 `a5a4` 相对候选并集损失 219 cp，也没有形成稳定修复。

新评测第 36 根也是反例：`g8h8` 被老师报告为三步被将杀，`g8f8` 为 -590 cp、未报告将杀。
CP + 排序的两种单步价值头都排错，搜索中两个分支的 WDL 又接近 -1；策略先验偏向 `g8h8`，
512 次展开后该版本没有访问到任何终局。旧小模型和 PUCT-512 在本次根评测避开了这条将杀变化。
这同时保留了评估错误和强制变化覆盖不足的证据，不能把平均 CP 损失的微降当作漏算已解决。

数据：[`known-failures/result.json`](evidence/rank-frontier-20261031/known-failures/result.json)、
[`remaining-errors.json`](evidence/rank-frontier-20261031/remaining-errors.json)。
对应原生完整树和每次校正事件存为各目录下的 `.json.gz`。

## 节点探索的追加诊断与独立验证

第 36 根的主分支 `g8h8` 展开 479 次，`Qxf7` 的先验约 0.549，却一次也没展开。
后续复核更正：这步吃子并不将军，而是形成将杀威胁；原来记为 `Qxf7+` 不准确。
原实现每逢全局第 16 次展开时探索，而这些轮次在根部被分配给另一分支；因此主要分支内部
仍然一直贪心。这是一个可重现的探索覆盖问题。

新增显式选项 `local_exploration=True`：按各节点自己的访问次数触发探索，并在未充分访问的
孩子之间优先使用策略先验。默认关闭，不改变已完成的第一批比较。
在诊断根重放中，`Qxf7` 从 0 次展开变成 213 次，访问终局数从 0 变成 109；
但三步将杀仍未形成完整证明，最终仍选择 `g8h8`。老师主变的最后一步将杀前节点没有展开，
覆盖改善不能当作选择已经正确。见 `local-mate-replay/` 和 `local-mate-coverage.json`。

为避免用该反例同时调参和报成绩，追加 64 盘更晚的新棋局根（源编号 47,254–63,643）。
这些棋局与前面训练、验证和评测棋局分离，根键与新边界数据交叉为零。
参数和模型检查点固定，对比开启/关闭探索；不再次训练或选模。

这批有 59 个全部候选可用 CP 的根、5 个含将杀标签的根：

| 方法 | 平均 CP 损失 | 损失 ≥100 cp（59 根） | 可避免被将杀事件（5 根） |
| --- | ---: | ---: | ---: |
| 旧模型，原探索 | 34.29 | 8 | 1 |
| 旧模型，按节点探索 | 28.07 | 6 | 0 |
| WDL，原探索 | 31.39 | 7 | 1 |
| WDL，按节点探索 | 39.39 | 6 | 0 |
| CP + 排序，原探索 | 31.95 | 7 | 2 |
| CP + 排序，按节点探索 | 30.73 | 7 | 0 |
| PUCT-31 | 30.10 | 7 | 0 |
| PUCT-512 | 27.76 | 6 | 0 |

CP + 排序开启新探索后的平均 CP 损失差为 -1.22，配对 95% 区间 [-10.66, +6.61]。
大失误修复一个、同时新引入一个。将杀事件的改善是这批的积极观察，样本只有五个，
且诊断根本身仍失败，不能推广为普遍解决。WDL 的平均损失还变差，说明更多覆盖也可能改变选择而引入损失。
中位耗时约 117 ms，大模型平均位置数仍为 31.5，没有增加神经网络预算。

再用相同四个开局对补做 8 局，CP + 排序开启新探索仍为 **0 胜 / 2 和 / 6 负**，无截断。
实际战绩没有支持整体增强，选项继续保持实验状态。
数据：[`local-plan.json`](evidence/rank-frontier-20261031/local-plan.json)、
[`local-comparison-analysis.json`](evidence/rank-frontier-20261031/local-comparison-analysis.json)、
`arena-cp-rank-local/result.json`。不同批次的候选集合与难度不同，未把两批均值混合成单一排名。

## 验证与后续优先级

训练、标注和评测均在本地完成。四个模型各用 100 个带合法历史的新根检查原生增量推理：
预测最大差小于 2.8e-6，增量累加器最大差小于 2.1e-6，没有发现可以解释漏算的导出错位。
见 [`student-analysis.json`](evidence/rank-frontier-20261031/student-analysis.json)。

最终完整测试 **125 passed in 26.54s**；当前源码的独立 UBSan 原生边界测试、Python 编译检查
与 `git diff --check` 均通过。日志：`output/rank-frontier-20261031/tests-final.txt`。
机器可读汇总与证据哈希：[`cp-rank-frontier-20261031.json`](evidence/cp-rank-frontier-20261031.json)。

保留新数据、CP/排序训练代码和所有消融检查点，默认模型及搜索不变。
下一步应优先检验校正可靠性和短强制变化的 CPU 证明预算；若让 CP 独立参与搜索打分，
还需要处理它与大模型 WDL 校正的尺度关系，不能直接混合后宣称提升。
这些是本轮反例支持的后续方向，尚未训练或实验验证。
