# 最佳优先 Minimax 与本地小评估器：首轮实验

后续已完成容量、训练分布、监督目标和搜索策略的受控分析，见
[搜索漏算诊断与改进](SEARCH_DIAGNOSIS_20261031.md)。本文件保留首轮原始实验条件和结果。

实现了 C++ CPU 增量评估、最佳优先 negamax、独立的大模型查询预算和按需校正。
现阶段完成了减少昂贵推理的工程验证，**没有达到现有 PUCT 的选着质量**，不替换默认引擎。

## 小模型与延长训练

- 107,073 参数，默认累加器宽度 128、隐藏层 32；两个行棋视角共享棋子格特征权重。
- 本地 RTX 4060 Laptop GPU 训练；导出 C++ CPU 权重 428,308 字节，约 418.3 KiB。
- 使用已有引擎搜索标签：先在 851,213 局面数据上启动，再使用 5,000,000 个训练局面扩展训练。
- 用户要求延长后，追加完成 **100,000 步**、409,500,288 次训练样本呈现。
- 这次追加训练在 75,000 步收到 SIGTERM，原因未知；从保存权重重建优化器，补完 25,000 步。
  这是两个训练阶段，不能称为优化器和数据游标无缝恢复。中断记录保存在输出目录。
- 固定的前 20,000 个验证局面，续训前 MSE 0.171975，选出的最佳权重 MSE **0.161799**，约下降 5.9%。
  最佳权重对应追加训练累计第 87,500 步；完成训练的最后权重与最佳权重分别保留。
- 另外检查全部 51,086 个验证局面：MSE **0.177953**，MAE 0.286659；材料基线 MSE 0.352471。
  选模子集和完整验证集的数值不可混为一谈。数据按局面哈希划分，不保证整盘棋或来源独立。

实际使用本地 Stockfish 18、每局面 20,000 nodes 新标注 2,048 个局面，保留作开发验证。
排除与完整 v2 数据库相同的 97 个局面后，剩余 1,951 个；它们仍可能来自相关棋局。
这组搜索标签上的 MSE 从短训模型的 0.266473 降至长训模型的 **0.254095**。
它说明延长训练改善了这组估值误差，不证明棋力提高或战术问题已经解决。

## 固定局面对照

最终采用固定长训权重，8 个已有开发开局，各次搜索使用冷树和空输出缓存。
大模型预热后串行测量，模型载入时间不计入。每个 Minimax 方法允许 512 次廉价展开，
PUCT 每步新增 512 次模拟、batch 64。最终默认关闭静态搜索；开启深度 2 的消融额外消耗大量
CPU 时间，未见稳定质量收益，因此仍作为显式选项保留。

| 方法 | 平均大模型评估局面数 | 每步中位耗时 | 候选集合内平均厘兵损失 |
| --- | ---: | ---: | ---: |
| 小模型 Minimax，无校正 | 0 | 0.0554 秒 | 70.000 |
| Minimax，预算 16 | 16 | 0.0900 秒 | 56.625 |
| Minimax，预算 32 | 32 | 0.1235 秒 | 28.000 |
| 原有多头 PUCT | 513 | 0.5045 秒 | 10.250 |

预算 32 时，大模型评估数约为原来的 **1/16**，本次冷树测量约快 **4.1 倍**；
但候选着法损失仍高于 PUCT。不能把提速说成算法已经更好。

“厘兵损失”来自 Stockfish 在各方法提出的着法与其初始最佳着的并集上，进行一次统一预算的
MultiPV 搜索；它相对于这个候选集合，不相对于数学上的最优着法。8 个局面也是开发用样本，
不是最终独立评测，不足以作显著性或 Elo 判断。

主测量：[`benchmark-final-serial/result.json`](evidence/cheap-minimax-20261031/benchmark-final-serial/result.json)。
`benchmark-final` 与 `benchmark-final-no-qsearch` 曾同时运行，仅保留为受资源竞争影响的消融记录；
上表使用随后单独串行重测的数据。早期实现与静态搜索试验也保留在 `benchmark-v1`、`v2`、`v3`。

## 对局与实现边界

前期短训权重已完成 2 个开局交换颜色的对局试运行。固定 Stockfish 18 每步 1,000 nodes，
无截断：Minimax 0 胜 1 和 3 负；PUCT 1 胜 1 和 2 负。这只证明对局链路正常运行，
样本过小，不能据此估计可靠棋力差。该试运行使用此前短训权重和深度 2 静态搜索，
与最终默认配置不同，原始配置、权重指纹和 PGN 均保留。

数据：[`arena-pilot/result.json`](evidence/cheap-minimax-20261031/arena-pilot/result.json)。
最终长训权重、512 次便宜展开、预算 32、关闭静态搜索的另一次开发对局也已完成：
同样 2 个开局交换颜色，**0 胜 0 和 4 负，无截断**；总耗时 15.89 秒，160 次选着，
共评估约 187.9 万个便宜局面、4,390 个大模型局面。实际大模型评估平均约 27.4 个局面/步。
这组结果同样不足以精确估计棋力，但没有支持当前方案替代 PUCT。
记录位于 [`arena-final/result.json`](evidence/cheap-minimax-20261031/arena-final/result.json)，
按其 `plan.json` 解释，不能与前期不同配置的胜率直接归因比较。

目前搜索是带神经估值锚点的 regularized minimax。直接大模型估值权重 .75、候选 Q 锚点 .25；
这两个系数是原型参数，不是误差概率或严格界。大模型校正被保留，避免廉价展开后立即消失；
精确胜负始终覆盖近似值，证明失败或和棋仍要求全部合法子节点。
目前没有复用整个搜索子树；只复用有效模型输入完全一致的网络输出。

## 验证与后续方向

完整项目测试 **99 项通过**；后续与权重读写、最终默认参数相关的 **15 项测试再次通过**。
UBSan 构建通过定向搜索测试；独立 C++ 检查通过 negamax 符号、校正持久性与精确证明边界。
最终长训权重在 250 个随机合法历史局面上，native 与 PyTorch 预测最大差约 3.52e-6，
增量累加器与完整重建最大差约 2.38e-6。

下一步的主要问题是小评估器及其搜索分布：一般局面估值误差仍大，Minimax 会放大部分乐观误差，
已有反例包括错误吃兵后丢子的变化。更值得做的是针对真实搜索边界、被反驳的候选和唯一防守
生成 Stockfish 搜索标签，并改善查询调度；仅增加便宜展开或重复训练步数不能保证解决这些问题。

构建、训练、使用、预算和复现实验命令见 [实现文档](../docs/BEST_FIRST_MINIMAX.md)。
