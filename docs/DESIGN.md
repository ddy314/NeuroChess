# 设计与实验边界

## 为什么这样做

用户要求 100M–200M 稠密深网、尽量利用 GPU，并希望先棋谱后 Stockfish。采用 155M 棋格编码器，单次计算所有合法动作，避免逐个候选动作重复运行整个 Transformer。policy 用于默认直接行棋，Q 用于蒸馏动作差异，WDL 用于一步展开。

[Chessformer 原文](https://arxiv.org/html/2605.19091v1)采用棋格 token、几何注意力偏置和源／目标动作头。这里借鉴棋格与动作头思路，初版采用标准 SDPA + 行列位置嵌入，尚未实现其 GAB。是否增加 GAB 必须在相同数据和计算预算下做消融；不能引用原文的 Elo 增益作为本模型效果。

[DeepMind Searchless Chess](https://github.com/google-deepmind/searchless_chess)给出大规模动作价值监督的强无搜索结果。其数据与模型规模、评分池和实验条件不同，不能据此保证本项目 155M 参数在当前预算下达到 2500。

## 数据路线

1. 人类棋谱预训练：标准棋、双方等级分门槛，丢弃解析错误／未知结果，默认每四个半回合取一个局面，跳过最早八个半回合。policy 学实际着法；WDL 学最终结果；Q 不监督。
2. Stockfish 蒸馏：优先选择预训练模型薄弱的战术、残局及自然局面。实现支持从真实棋谱抽取局面，再用固定节点预算、多进程、MultiPV 生成标签。初始 pilot 用低预算验证流程，正式标签应提高预算。
3. 先跑固定对局套件观察强度，再决定增加数据、提高标注质量、调损失权重或扩展搜索。尚未实现自动难例挖掘、自我对弈、MCTS、分布式训练或自动课程学习。

Lichess 的[公开棋谱及评估数据库](https://database.lichess.org/)可降低收集成本。当前已实现 PGN 导入和本地 Stockfish 标注；尚未实现 ChessBench 或 Lichess eval JSONL 导入。不要把下载好的其他格式直接当作本项目分片。

### 标签和历史限制

- WDL 顺序始终为当前行棋方的胜、和、负。Stockfish 分数使用 python-chess `sf16` 曲线转 WDL，是训练目标近似，不是引擎的原生概率保证。
- 蒸馏策略为已标注候选动作之间按预期胜负值 softmax，未标注动作 policy 为零，Q 使用掩码。MultiPV=8 不等于标注了所有合法动作。
- 因此默认用 policy 行棋；Q-only 仅用于实验。要认真评估 Q-only，先用 `--multipv 256` 标注全部合法动作，再做独立测试。
- FEN 无法恢复完整历史。蒸馏重复次数特征为零；棋谱预训练保留可恢复的重复信息。网络也没有完整历史 token，最终和棋判定由规则引擎处理。
- 局面哈希决定 99:1 训练／验证划分，忽略半回合计数等历史，避免相同棋盘跨分割。**这不是按整盘棋或时间划分**；相邻局面仍有关联。它适合训练监控，不足以证明泛化。
- `audit` 会检查精确局面泄漏、标签、padding、重复动作和分片计数；单文件转换默认只统计同一 split 内重复；新版近期 profile 启用 SQLite 精确局面去重，按来源顺序保留第一份标签。
- 最终测试必须另用时间或来源隔离的开局／完整对局／战术题，并排除与训练数据的局面重叠。禁止在最终测试集上反复选择模型。

## 网络与性能

配置 `configs/base.json`：16×896，14 heads，MLP 4×，动作头隐藏维 256，总参数 155,000,581。合法动作 padded 到 256；结构编码为 `(from * 64 + to) * 5 + promotion`，保留全部升变。

棋盘翻转只沿 rank，不沿 file；王车易位的左右含义保持一致。训练仅接受标准棋，非 Chess960。输入包括易位权、吃过路兵格、半回合时钟、重复状态、是否将军、颜色和回合数。

FP32 保存主权重和 Adam 状态；T4 使用 FP16 autocast 和 GradScaler，原生 BF16 卡可以自动使用 BF16。SDPA 由 PyTorch 按设备选内核；不能把调用 SDPA 等同于必然启用了 FlashAttention。编译可选，需实测冷启动、重编译和稳定吞吐。尾批保持有效，变 batch shape 可能触发重编译。

数据文件为结构化 NPY，约 1.9 KiB/局面（以 manifest 实测 row_bytes 为准）；一亿局面会占用大量磁盘。不要把巨大数据、每步 checkpoint 或优化器文件反复从 Drive 读取。训练数据放 VM 本地，检查点按较稀的间隔写持久存储。

## 如何定义 2500

2500 必须绑定评分池、时间控制、硬件、开局分布和搜索模式。Lichess blitz、FIDE 与引擎测试池数值不能直接互换。

当前评测器采用相同开局正反颜色对局，固定对手 Stockfish 节点预算，输出完成／截断局数和按开局对 bootstrap 的胜率区间。达到最大步数而未结束的对局记为 `*`，不冒充和棋；有截断时不能据完整局子集推断无偏总体胜率。小于足够开局数量的 bootstrap 区间也不能用于宣称棋力。

固定节点 Stockfish 或 `UCI_Elo=2500` 不是绝对 Elo 标尺。要宣称 2500+，仍需可靠的已校准对手池及足量正式对局。当前仓库没有完成该步骤。
