# Fresh-v4 新数据与 A/B 实验

本实验在已完成的 `curriculum-v3` 之后，计划检验新增局面和教师标注是否改善当前模型，而不是只根据参考验证 loss 选择新默认权重。配置见 [`configs/fresh-v4.json`](../configs/fresh-v4.json)。

2026-10-31 的历史快照：50 万训练局面及独立的 1 万验证、2 千测试局面已选定，当时两个云端 CPU 教师正在标注。到 2026-11-06 的整理中，没有原计划两组训练及最终评测的完整闭环证据。后续定向数据、三头联合训练、动态候选、PAWN 与 Lichess 使用独立分支和协议，见[累计进展](../reports/TRAINING_PROGRESS.md)。不能把本文或旧状态文件解释为当前活动任务，也不能将后续独立训练补记为原 A/B 完成。

## 数据和协议

- 训练集目标按战术／残局／开局 60%／30%／10% 选取；对已有核心和人类回放的局面键做排重，并按来源棋局隔离新集合。不能确认旧预训练来源棋局完全不重叠。[选择审计](../reports/evidence/training-progress/fresh-v4-selection-audit.json)记录有限的实际核验范围。
- Stockfish 教师采用 100,000 nodes 主标注、10,000 nodes 粗筛；发现与原题答案冲突的有限预算标签时，需要更深复核，不能自动认定原题错误。后续代码增加 1M-node 质量复核，未解决分歧的样本只保留来源 Policy，屏蔽 Q/Value，并保留原题标签作审计。
- 两组从同一个第三阶段选中权重出发，均重置优化器，各训练 2,000 次更新；新数据组使用配置中的核心／新数据／人类策略／开局策略混合。具体配置和实际交付以运行时产物为准。
- 计划在冻结的新题测试集上检查直接和锁定两秒 PUCT 搜索首步，并对相同开局使用 Stockfish 18、1,000 nodes 进行换色对局。搜索协议来自 `configs/puct-2s-local.json`，不再以旧 512 次搜索代替固定质量参考；L4 上同一配置不证明与本地基线棋力等价。新题首步正确率不是完整解题率，有限预算对局也不是绝对 Elo 标定。

代码入口为 `scripts/fresh_v4_prepare_cloud.py`、`scripts/fresh_v4_teacher_extra.py`、`scripts/fresh_v4_train_cloud.py`。它们依赖云端数据、现有检查点和授权后的 Drive；启动前应核对运行状态、数据准备和质量门槛，避免重复创建实例或并发写同一输出。
