# 引擎数据扩容与第 1500 步接续

本阶段从 `engine-v1` 的第 1500 步完整 checkpoint 接续。原训练集为 842756 个引擎局面，扩到 5000000 个；新增训练局面 4157244 个，原训练与验证分片保留。所有源记录继续要求搜索深度至少 20、至少 50 千节点、至少两个合法候选着法。按忽略历史计数的局面键去重，并保持原来的局面哈希划分。已保存评测局面继续排除。

数据由相同版本的 Lichess evaluations 文件扩展读取前缀得到，并非全库均匀抽样。下载固定 ETag，逐段检查 HTTP Content-Range 和实际长度，遇到源站 429 遵循 Retry-After 等待；已关闭的分片可以重新索引后继续导入。未达到目标不会发布完整 manifest。完整审计和上传后的 SHA256 验证通过后才允许开始训练。

训练主验证集固定为原来 8457 个局面，保证扩容前后可以比较。扩容产生的额外验证局面保留在新数据集中，供后续独立检查；它们不进入训练，也不混入当前主验证曲线。该哈希留出只隔离相同局面，不能保证同一棋局或相邻局面的独立性。

配置为 `configs/phase2-expanded-l4.json`：有效 batch 64×16=1024，约 7/8 引擎局面和 1/8 人类策略回放，BF16、编译、2 个加载进程。新阶段计划 6000 次更新，约呈现 537.6 万引擎局面，即扩容训练集约 1.08 遍。学习率峰值 3e-5，100 步预热，再余弦衰减；Q 权重保持 0.5，不重新执行 Q 预热。每 250 步验证并保存，每 1000 步运行小型策略对局监控。

`--continue-from` 保留模型、AdamW 动量和精度缩放状态，重置数据游标、阶段步数和学习率计划；启动时在固定验证集重新测量基线。新阶段的图表从 0 计步，`origin_step=1500` 和 `cumulative_step` 记录接续关系。`--resume` 继续本阶段，仍要求数据指纹和训练配置匹配；`--init` 只加载权重。测试检查 Adam 更新计数延续、固定验证集、精确断点恢复，以及参考数据变化时拒绝恢复。

启动器 `scripts/expanded_colab.py` 复用现有 L4 与已挂载的 Drive，不创建新实例。它先将新数据压缩缓存写入 Drive 并读取校验，然后运行 25 步接续检查，确认 Adam 的更新计数为 1525、checkpoint 已同步，再自动恢复到本阶段 6000 步计划。原 `engine-v1` 结果单独保留，新运行名为 `engine-v2-expanded`。

训练结果每 30 秒尝试同步到 Drive。模型每 250 步保存，日志进度不代表可恢复模型的进度。数据压缩缓存、训练代码、阶段配置、父 checkpoint 记录与接续检查结果均持久化；新实例仍需重新挂载 Drive、恢复代码和数据。源码与配置是备份，不是自动创建实例的授权。

本轮已启用完成后自动释放实例。云端 `neurochess.autostop` 收尾进程绑定当前启动器的 PID 和进程启动标识，每 30 秒检查一次；不依赖本机在线。它等待启动器结束且输出最终持久化成功标记，再确认本地和 Drive 状态均为 6000 步完成，重新同步结果，读取校验模型、优化器 checkpoint、训练代码、日志和数据缓存。核验记录先写入 Drive，随后使用 Colab 运行环境自带的管理接口释放当前实例。训练失败、未达到计划步数或校验失败时保留实例，原因记录在 `autostop.json`。仅重启训练代码不会激活已经在运行的旧启动器，因此本轮由独立收尾进程接管；后续新启动器在成功路径调用同一核验函数，`NC_AUTO_STOP=0` 可显式关闭其自动释放。

验证 loss 和小型对局监控不等于绝对 Elo。是否继续增加训练轮数，应依据固定验证曲线和相同预算的策略/MCTS 对局结果。
